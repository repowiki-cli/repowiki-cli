# Harness Output Optimization Design

**Date:** 2026-05-18
**Status:** Approved

## Problem

The harness (`--harness=claude-code`, `--harness=cursor`) writes every module-level node as a table row into `CLAUDE.md` / `.cursorrules`. For a project with N TypeScript files, the output contains N rows of low-value one-sentence summaries. At scale (hundreds or thousands of files), this exhausts AI context windows and provides little architectural value over what the wiki files already contain.

## Goal

Replace the module-level summary table with a compact architecture tree that conveys structural context without overwhelming the AI context window.

## Design

### Output Format

**Before (current):**
```markdown
## RepoWiki — Auto-generated Context

> Generated by `repowiki wiki generate --harness=claude-code`. ...

### Project Overview
[root summary]

### Key Modules
| Path | Description |
|------|-------------|
| `plugin-wiki/src/analyzers/typescript/TypeScriptAnalyzer` | The TypeScriptAnalyzer class ... |
| `plugin-wiki/src/backends/LocalMarkdownBackend` | The LocalMarkdownBackend class ... |
... (one row per .ts file)
```

**After — ClaudeCodeHarness (CLAUDE.md):**
```markdown
## RepoWiki — Auto-generated Context

> Generated by `repowiki wiki generate --harness=claude-code`. Do not edit this block manually.

### Project Overview
[root summary — unchanged]

### Architecture
`packages/core`             — Shared TypeScript interfaces with zero runtime dependencies.
`packages/cli`              — oclif CLI entry point; aggregates the three plugins.
`packages/plugin-wiki`      — Wiki generation pipeline (analyze → summarize → render → write).
`packages/plugin-wiki/analyzers/typescript` — TypeScript AST analysis via tree-sitter.
`packages/plugin-wiki/backends`             — Local markdown and manifest storage.

> For per-file summaries, see `.repowiki/`.
```

**After — CursorHarness (.cursorrules):**
```markdown
# RepoWiki Context

When working in this codebase, use the following context:

## Project Overview
[root summary — unchanged]

## Architecture
`packages/core`             — Shared TypeScript interfaces with zero runtime dependencies.
`packages/cli`              — oclif CLI entry point; aggregates the three plugins.
`packages/plugin-wiki`      — Wiki generation pipeline (analyze → summarize → render → write).
`packages/plugin-wiki/analyzers/typescript` — TypeScript AST analysis via tree-sitter.
`packages/plugin-wiki/backends`             — Local markdown and manifest storage.

> For per-file summaries, see `.repowiki/`.
```

Note: `CursorHarness` preserves its existing `#`/`##` heading levels and intro sentence; only the content after `## Key Modules` changes.

### Node Selection

- **Include:** `package` and `directory` type nodes
- **Exclude:** `module` nodes (individual `.ts` files)
- **Order:** Sort by `path` (ascending lexicographic), same as current

Because `collectNodes` accepts a single `NodeType`, implementation requires two calls:
```typescript
const nodes = [
  ...collectNodes(root, 'package'),
  ...collectNodes(root, 'directory'),
].sort((a, b) => a.path.localeCompare(b.path));
```

The number of package/directory nodes is typically 5–20, regardless of how many source files the project contains. The root node type is always `project`, so `collectNodes` will never include it in the result. If there are no such nodes (e.g., a flat single-package repo with no subdirectories), the Architecture section and trailing reference line are both omitted.

### Line Format

Each node renders as one line:
```
`{node.path}`{padding} — {first sentence of node.summary}
```

**First sentence extraction:** Take everything up to and including the first `.` that is followed by whitespace or end-of-string. The trailing period is included in the output. If the result is empty, fall back to `"(no summary)"`. Reference pseudocode:
```typescript
function firstSentence(summary: string): string {
  const match = summary.match(/^.*?\.(?=\s|$)/s);
  const s = (match ? match[0] : summary).trim();
  return s || '(no summary)';
}
```

**Padding:** Align `—` separators by padding each backtick-wrapped path to the length of the longest such string + 2. Reference pseudocode:
```typescript
const backtickPaths = nodes.map(n => `\`${n.path}\``);
const maxLen = Math.max(...backtickPaths.map(s => s.length));
const lines = nodes.map((n, i) =>
  `${backtickPaths[i].padEnd(maxLen + 2)} — ${firstSentence(n.summary)}`
);
```

Assumes all `node.path` values are ASCII; non-ASCII paths may misalign visually but will not cause errors.

Example (`` `packages/core` `` = 15 chars, `` `packages/plugin-wiki` `` = 22 chars, maxLen = 22, padEnd(24)):
```
`packages/core`         — Shared TypeScript interfaces with zero runtime dependencies.
`packages/plugin-wiki`  — Wiki generation pipeline (analyze → summarize → render → write).
```

**Empty node list:** If `nodes.length === 0`, the `### Architecture` heading, all node lines, and the trailing reference line are all omitted. The output ends after `### Project Overview` with no trailing newline beyond the summary text itself (same as current behavior).

### Trailing Reference Line

When the Architecture section is present, append a fixed prose line:
```
> For per-file summaries, see `.repowiki/`.
```

This always uses the literal string `.repowiki/`. The `generate(root: AnalyzedNode): string` signature does not receive `outputPath`; changing the interface or call site is out of scope. If a user's `--output-path` differs from `.repowiki`, the reference line is approximate documentation, not a guaranteed accurate path.

## Scope

### Files Changed

| File | Change |
|------|--------|
| `packages/plugin-wiki/src/harness/ClaudeCodeHarness.ts` | Replace module table with package/directory tree |
| `packages/plugin-wiki/src/harness/CursorHarness.ts` | Same change, adapted for `.cursorrules` format |
| `packages/plugin-wiki/src/harness/__tests__/harness.test.ts` | Rebuild `mockRoot` fixture to include at least one `package` node and one `directory` node with paths of different lengths (to exercise padding alignment), plus at least one `module` node (to verify it is excluded). Rename `'generate includes project summary and module table'` → `'generate includes project summary and architecture section'`. Rename `'generate only lists module-type nodes'` → `'generate only lists package and directory nodes'`. Update all assertions for new output format. Add a test for the empty-node-list case (only `project`/`module` nodes → Architecture section and reference line both absent). |

### Files Unchanged

- `HarnessWriter.ts` — tag-based write logic is not affected
- `GeneratePipeline.ts` — call site is not affected
- `types.ts`, `GenerateOptions` — no new flags or options
- CLI flags — `--harness` flag behavior unchanged

## Out of Scope

- `--harness-depth` or other granularity flags (YAGNI)
- Module-level sampling or importance scoring
- Changes to wiki file generation or the manifest

## Success Criteria

1. `ClaudeCodeHarness.generate()` and `CursorHarness.generate()` no longer reference `module` nodes.
2. Output contains only `package` and `directory` nodes.
3. For this repo (~5 packages, ~10 directories), the harness block shrinks from ~30 rows to ~15 rows. For a 1000-file project, from ~1000 rows to ~20 rows.
4. Existing tests updated and passing; no new test failures.
5. A changeset is included.
